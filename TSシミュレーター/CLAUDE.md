# CLAUDE.md

## プロジェクト
トータルステーション（TS）の据付と観測を練習できる3Dシミュレーター。
Built with Claude: Japan 2026 の出展作品。**仕様はすべて `docs/SPEC.md` にある。作業前に必ず読むこと。**

## オーナーについて
- オーナー（豆虎）は**自分でコードを書かない**。説明・報告・質問はすべて**日本語**で、専門用語は短く補足する。
- 測量の現場経験はオーナーが持っている。**測量の挙動や手順で迷ったら、推測で決めずにオーナーに聞く。**

## 最重要ルール（必ず守る）
1. **頼まれたことだけをやる。** 頼まれていないファイルの変更、リファクタリング、名前の変更、依存関係の追加（`package.json`・`Cargo.toml`とも）、設定の変更はしない。
2. **仕様と違うことをしたくなったら、手を動かす前に提案して許可を取る。** 黙って仕様を変えない。
3. **作業が終わったら、変更したファイルと変更内容を一覧で報告する。** 「何をしたか」「何をしなかったか」「確認できていないこと」を分けて書く。
4. テストが通らない状態で「完了」と言わない。通らない場合はその事実を報告する。テストを消す・弱める・飛ばすことで通さない。
5. ファイルの削除、`git push --force`、履歴の書き換えは、オーナーの明示的な許可がない限りしない。
6. `docs/SPEC.md` は**オーナーの許可なく書き換えない**。仕様の変更はオーナーが決める。

## 技術構成
- **計算コア：Rust**（WASMにしてブラウザで動かす。wasm-bindgen / wasm-pack）
- 表示側：TypeScript / React / Three.js / Vite
- テスト：`cargo test`（物理・判定・計算）、Vitest（WASMとのつなぎ目のみ）
- UIパネルはReact。3D描画はThree.jsを直接使う（**React Three Fiberは使わない**）
- Web版はVercel（デスクトップアプリ版は廃止。2026-11-05）
- Rustの版は `rust-toolchain.toml` で固定する

## ディレクトリ
```
crates/
  core/     状態・物理・判定・観測の計算・タイマー（純粋なRust。WASM・ブラウザに依存しない）
  wasm/     coreをTypeScriptに公開する薄い層（wasm-bindgen）。計算は書かない
src/
  bridge/   WASMの読み込みと呼び出し（TypeScriptからコアに触る窓口はここだけ）
  render/   Three.jsのシーン、モデル、カメラ
  ui/       画面のパネル（React。上部・左・右・結果画面）
  main.tsx  起動処理
tests/      Vitest（WASMとのつなぎ目の確認）
docs/       仕様書
```

## 設計の決まりごと
- **物理・判定・座標計算はすべて `crates/core` に書く。** TypeScript側（`src/`）には計算を書かない。`render` と `ui` はコアの結果を表示するだけ。
- **`crates/wasm` に計算ロジックを書かない。** `wasm` は受け渡しだけ。
- `crates/core` では**panicさせない**。`unwrap()`・`expect()` は使わず、失敗は値（`Result`など）で返す。`unsafe` は使わない。
- **`src/render/` にReactを持ち込まない。** Three.jsの描画ループはReactから切り離す。
- `src/` からWASMを呼ぶのは `src/bridge/` だけ。WASMとのやり取りは**1フレームにつき「操作を渡す」「結果をまとめて受け取る」の最小限**にする。
- 気泡・液晶・求心ズレなど**毎フレーム変わる数値はReactの状態に入れない**。refで表示を直接書き換える。Reactの状態は、ステップ・モード・結果など変化の少ないものだけ。
- 整準ネジ・気泡・液晶・レーザー求心は、**1つの状態から計算する**（SPEC 6章）。表示ごとに別々の値を持たない。
- 内部の単位は **mm とラジアン**、計算は **f64**。度分秒への変換はコアの関数で行い、表示の直前だけで使う。
- 許容値などの数値は `crates/core` の設定ファイル（例：`config.rs`）1か所にまとめる（SPEC 6.7 で「確定」の値は変えない。「仮」の値は調整してよいが、変えたら報告する）。
- 必ず守る挙動（左手親指の法則など）は SPEC 6.4 を参照し、`cargo test` で確認する。

## 3Dと軽さ
- オーナーの確認用PCは **Core i5-6200U（内蔵GPU HD 520）** のみ。ここで普通に操作でき、デモ録画がカクつかないことが最低ライン。
- 動的な影は1灯のみ。ブルーム等の後処理は使わない。pixel ratio に上限を設ける。
- 重くなる変更（ポリゴン増、影の追加、後処理）は、入れる前に提案する。
- WASMは本番ビルドで最適化してサイズを小さくする。
- TS本体は特定メーカーの製品に似せない。ロゴ・メーカー名は入れない。電子平板の画面も特定製品を真似ない。

## 素材
- 馬毛島の現場写真・映像は**絶対に使わない**。
- 既知点・設計値の座標は架空のものを使う。実在の現場座標は使わない。
- 外部の画像や素材を追加するときは、出典とライセンスを `README.md` に記録する。

## コマンド
```
npm install          依存関係のインストール
npm run build:wasm   WASMのビルド（wasm-pack）
npm run dev          開発サーバー
npm run build        Web版のビルド（WASMのビルドを含む）
cargo test           コアのテスト
npm test             Vitest（つなぎ目の確認）
```
※ 骨組みを作ったときに、実際のコマンドと一致しているか確認して更新すること（この変更は許可不要）。

## 確認の手順
変更のたびに：
1. `cargo test` が通ることを確認
2. `npm test` が通ることを確認
3. `npm run build` が通ることを確認
4. 見た目が変わる変更は、何がどう変わったかを報告する

## コミット
- コミットは機能単位で小さく分ける。
- コミットメッセージは日本語で、何を変えたかを1行で書く。
- `main` ブランチへの直接pushは、オーナーの指示があるときだけ。
